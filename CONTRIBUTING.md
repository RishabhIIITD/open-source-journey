# Contributing to open-source-journey

Thank you for your interest in contributing to the **open-source-journey** repository. This repository serves as a curated catalog of upstream open-source contributions, technical deep dives, and architectural walkthroughs across production codebases.

## Contribution Guidelines

### Adding a New Contribution Case Study

When documenting a new open-source contribution, please structure the documentation in the `contributions/` directory following this format:

1. **Title & Target**: Repository name, issue title, issue number, and upstream PR link.
2. **Problem Statement**: Clear description of the bug, missing capability, or performance bottleneck.
3. **Root Cause Analysis**: Code analysis of the underlying codebase explaining why the issue occurs.
4. **Implementation Walkthrough**: Explanation of the patch with before/after code blocks.
5. **Testing & Verification**: Unit tests, regression tests, and verification commands executed.
6. **Artifact References**: Links to generated markdown walkthroughs and PDF guides.

### Quality Standards

- Maintain clear technical precision and reference relevant specifications (e.g., RFC standards, library documentation).
- Include reproducible test steps.
- Ensure all diagrams and markdown links are valid.

### Co-authoring & Collaboration

When collaborating on contributions, attribute co-authors in git commit trailers using the standard format:
```text
Co-authored-by: Collaborator Name <collaborator@email.com>
```
This ensures all contributors are properly credited in GitHub's commit graphs and contribution insights.
